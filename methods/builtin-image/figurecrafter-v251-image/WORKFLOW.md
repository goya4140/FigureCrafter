# FigureCrafter v2.5.1 Image backend addendum

Reuse FigureCrafter scientific inputs, paper reading, reference learning, representation planning and model review. This workflow overrides the inherited native drawing/execute/finish contract ONLY for the raster backend. Do not run native builders, Decomposer, SAM/OCR, or read another method's reconstructed/edited outputs. Inputs are the Method text and three reference PNGs, plus explicitly captured upstream scientific planning text. A same-paper/same-context pilot is not a blind evaluation.

Read the inherited four general guides and source paper; read complete Method text and all reference images. Write understanding.md, representation.md and decision.md through write_file. Generate a scientific image prompt from these records. Request generation through image_request, execute the returned image_gen arguments using the built-in image_gen tool, and register the actual returned local file with image_result. The backend never fabricates a model response or silently switches providers.

Observe the registered full image AND publication preview, then write a scientific/visual review. Each review JSON has status accepted or needs_edit, observations, findings [{id,severity,region,problem,source}], and limitations. Model judgment remains an attestation, not automatic scientific validation. A generation is raster output, not evidence of correctness.

For edits, image_request takes an existing reviewed parent iteration and precise edit text. Bind the request to the immutable parent image hash and findings. Use only that parent's image as edit target. State what changes and what must remain: scientific identities, images, labels, color roles and unaffected geometry. Supply paper-based correction reasons; inspect the whole edited image for regressions and recheck text, routes and protected elements. Rejected output remains recorded; a later request may branch from an earlier reviewed image. There is no forced acceptance after a fixed number of edits.

Only image_gen creates or edits figure content. Code may inspect files, copy original outputs, pad a near16:9 result with white borders without stretching/cropping, produce proportional publication previews and wrap actual raster pixels into PDF. Preserve the raw generated file and record exact padding. Deliver final PNG, image-based PDF, caption and review; never call them native/editable figures. Do not produce an image-in-PPTX and claim editability.

Finish requires accepted review, actual matching pixel-observation events, scientific notes, observed references and complete Method text. Save all requests, prompts, parent hashes, raw outputs, provider metadata, reviews and failed attempts. Unknown model identifiers, token usage, cost and elapsed generation time stay unknown unless exposed by the provider; don't estimate them from file timestamps. Frozen inputs and output hashes prove consistency, not science or actual human acceptance.

User policy2026-10-24: at most3 image edit requests per sample in total. Initial generation does not count. All branches and failed/abandoned edit requests consume the same budget; a new generation or restarting a session must not be used to evade it. Prioritize scientific defects in each edit, compare whole-image quality, and select the best scientifically acceptable existing iteration. At the limit, if high-severity errors remain, stop image editing and report unresolved defects; never lower the acceptance standard just to finish. Historical7-edit RoboScape run is preserved as pre-policy evidence.

The complete original v2.5.1 MODEL text and four guides are inherited verbatim. This addendum changes only raster authoring/result registration and format-specific delivery mechanics. All original scientific reasoning, reference interpretation, representation/design, pixel review and correction quality requirements remain in force. No sample-specific scientific prompt, label/photo/object limits or code-size limits are added. Model: gpt-6.1-sol. Image generation/editing: actual Codex built-in image_gen only. Native images/results from other methods are not inputs. A shared RoboScape edit budget, when configured, covers Image and Hybrid proposal branches together, including failures.
